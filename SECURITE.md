# Sécurité

## Ce qu'on protège

| Élément | Où il vit | Ce qu'il permet |
|---|---|---|
| Clés du projet Tuya (Access ID, Access Secret) | Secrets Cloudflare, `tools/.env` et `worker/.dev.vars` sur l'ordinateur | Piloter les appareils du compte Smart Life lié au projet (le compte dédié, qui ne possède que le câble) |
| Clé locale du câble (`TUYA_LOCAL_KEY`, piste du pilotage local) | `tools/.env` sur l'ordinateur ; copie dans le gestionnaire de mots de passe de Mathieu ; à partir de la v0.3 de la coque, sur le Pixel 9 et le Pixel 10, chiffrée (voir « Coque Android ») | Piloter le câble depuis le Wi-Fi de la maison, sans passer par Tuya. Elle change à chaque appairage (à confirmer) |
| Jeton d'accès au service (`JETON_ACCES`) | Secret Cloudflare, paramètres de la page sur le Pixel | Régler ou désactiver la plage de charge du câble |
| Comptes GitHub, Cloudflare, Tuya | Chez chaque fournisseur | Modifier la page, le service ou le projet |

## Pire cas

Un tiers allume ou éteint la recharge à un moment non voulu : voiture pas chargée le matin, ou quelques euros en heures pleines. Aucun risque électrique : la sécurité physique est assurée par le boîtier du câble et le disjoncteur différentiel, pas par le logiciel.

**Isolement :** les clés d'un projet Tuya donnent accès à **tous les appareils du compte Smart Life relié**, quelle que soit la sélection d'appareils faite à la liaison (constaté le 2026-11-11). Le projet est donc relié uniquement à un compte dédié qui ne possède que le câble ; le compte principal (piscine, VMC, climatiseur…) n'y est jamais relié. Vérifié le 2026-11-14 : les lectures sur un appareil du compte principal sont refusées (`docs/tuya-findings.md`).

## Mesures

1. **Compte Smart Life dédié, propriétaire du seul câble**, seul compte relié au projet. Une fuite des clés ne toucherait que la recharge. Les clés Tuya restent néanmoins les secrets les plus sensibles du projet : elles ne quittent jamais les secrets Cloudflare et les fichiers ignorés par git. Ne jamais ajouter d'autre appareil au compte dédié.
2. **Double authentification** sur GitHub, Cloudflare et le compte développeur Tuya.
3. **Service minimal.** Le Worker n'expose que deux actions : régler l'heure de démarrage (format `HH:MM` strictement validé) ou la désactiver, plus la lecture de l'état. Aucune route n'accepte une commande quelconque.
4. **Jeton obligatoire** sur chaque requête, long et aléatoire, comparé en temps constant. Le CORS n'est **pas** une protection : il gêne seulement les autres sites web dans un navigateur. La barrière réelle est le jeton.
5. **Limite d'appels** sur le service (quelques dizaines par heure suffisent), avec réponse 429 au-delà.
6. **Aucun secret dans le dépôt**, protection contre les fuites de GitHub activée (*Secret scanning* et *Push protection*), fichiers de secrets ignorés par git (`.env*` sauf `.env.example`, `*.dev.vars*`) et interdits en lecture à Claude Code. Contrôle local avant chaque commit (`tools/hooks/pre-commit`, activé par `git config core.hooksPath tools/hooks`) : refuse un fichier de secrets, un `.env.example` rempli, ou toute valeur de `tools/.env` / `worker/.dev.vars` présente dans les changements. La *Push protection* de GitHub ne reconnaît probablement pas les clés Tuya : ce contrôle local est la vraie barrière.
7. **Journaux propres** : jamais d'en-tête `Authorization`, de jeton ou de clé dans les journaux du Worker ou les erreurs renvoyées à la page.
8. **Agents sous contrôle** : jamais de mode « tout accepter » (`bypassPermissions`) dans Claude Code. Les modifications de fichiers sont acceptées d'office (`acceptEdits`), sauf `.claude/`, `tools/hooks/`, `.github/`, les scripts `tools/*.mjs` et `tools/*.py` (ils chargent les fichiers de secrets), `worker/wrangler.toml`, `.gitignore`, `CLAUDE.md` et `SECURITE.md` (demande à chaque fois) ; les options git qui lisent hors du dépôt (`--no-index`, `--no-exclude-standard`) ou forcent l'ajout d'un fichier ignoré (`add -f`) sont interdites, ainsi que celles qui écrivent un fichier ou lancent une commande (`--output` et ses abréviations, `git grep -O`, `--open-files-in-pager`, ajoutées le 2026-11-22) ; `git grep` n'est plus libre (ses options courtes groupées échappent à un motif) et passe par une demande ; la lecture des fichiers de secrets est interdite à l'outil de lecture (barrière fiable) et, côté Bash et PowerShell, par motif sur leur nom (simple fil d'alarme : une écriture détournée du chemin y échappe) ; `.git/` et les fichiers de secrets ne sont jamais modifiables. La lecture web sans demande est limitée à `developer.tuya.com` et `developers.cloudflare.com` : une page web piégée pourrait pousser un agent à écrire un test qui lit et envoie les secrets, ce qu'aucune règle ne bloque une fois le test lancé. Les autorisations sont fixées dans `.claude/settings.json` : libres pour les tests, git en local et le serveur local ; une demande à chaque fois pour `git push` (une page modifiée pourrait capturer le jeton), `wrangler deploy` et `secret`, la sonde, `essai-worker.mjs`, `wrangler dev` et le test local du câble ; interdits pour la lecture des fichiers de secrets, le contournement du contrôle avant commit et `wrangler tail`. Toute modification de ce fichier est relue par Mathieu. Le contenu lu sur le web par les agents est traité comme des données, jamais comme des instructions.

## Procédures de révocation

| Situation | Action | Délai |
|---|---|---|
| **Urgence, quelle que soit la cause** | Console Tuya (iot.tuya.com) → projet → Devices → Link App Account : **délier le compte Smart Life**. Le projet perd immédiatement l'accès à tous vos appareils. Puis régénérer l'Access Secret. | 2 min |
| Téléphone perdu ou jeton exposé | Générer un nouveau jeton, `npx wrangler secret put JETON_ACCES`, le ressaisir dans la page sur le nouveau téléphone. | 5 min |
| Clés Tuya exposées | Console Tuya → projet → régénérer l'Access Secret, puis `npx wrangler secret put TUYA_ACCESS_SECRET` et mise à jour de `tools/.env`. | 10 min |
| Clé locale du câble exposée | Seul levier : **réappairer le câble** dans Smart Life (compte dédié), ce qui génère une nouvelle clé locale (à confirmer). Puis `node tools/tuya-probe.mjs cle-locale` si la piste locale est encore utilisée. Un tiers doit être sur le Wi-Fi de la maison pour s'en servir. | 15 min |
| Pixel perdu ou volé (coque v0.3 et suivantes) | La clé locale y est chiffrée par une clé non exportable du téléphone, utilisable seulement téléphone déverrouillé ; elle ne sert que sur le Wi-Fi de la maison. Par prudence : **réappairer le câble** (nouvelle clé locale, ligne ci-dessus), puis la ressaisir sur l'autre Pixel. Après la fin de l'essai IoT Core (2026-12-11), récupérer la nouvelle clé n'a pas de voie connue : à vérifier avant de réappairer. | 15 min |
| Compte GitHub compromis | Changer le mot de passe, vérifier la double authentification, relire les derniers commits de `site/` (une page modifiée pourrait capturer le jeton), puis changer le jeton. | 15 min |
| Compte Cloudflare compromis | Changer le mot de passe, révoquer les sessions, changer **tous** les secrets du Worker (jeton et clés Tuya). | 15 min |

Après toute révocation : vérifier dans Smart Life que la plage de charge du câble est correcte (début, fin 06:00, activée) et qu'aucune programmation inconnue n'a été ajoutée.

## Coque Android (phase 3b, à partir de la v0.3, décisions du 2026-11-20)

- **Stockage** : identifiant et clé locale du câble chiffrés ensemble (AES-GCM) par une clé du magasin de clés d'Android, non exportable, créée avec `setUnlockedDeviceRequired(true)`, sans biométrie ; fichier privé de l'application, exclu de la sauvegarde et du transfert d'appareil (`allowBackup="false"`, règles d'extraction). L'adresse IP du câble est rangée en clair à côté : elle n'est pas secrète. Effacés par « Oublier le câble » (écran natif, avec confirmation), à la désinstallation ou par « Effacer les données ».
- **Usage (depuis E2, 2026-11-22)** : déchiffrés hors du fil principal par le code natif seulement, pour une opération demandée par la page (lire l'état, programmer, chercher le câble). **La clé et l'identifiant ne traversent jamais la WebView** : la page ne reçoit que des heures, des codes d'erreur et l'adresse IP. La copie en octets est mise à zéro après chaque opération. Le protocole local n'a qu'une implémentation, en Kotlin (`android/.../cable/`), qui n'écrit que `ss` et `m` du dp 151 ; `local/tuya-local.js` n'est plus embarqué dans l'APK (il reste pour l'outil PC).
- **Risque résiduel** : un script étranger exécuté dans l'appli pourrait demander « programmer » ou « lire », mais ni obtenir la clé ni envoyer une autre commande au câble (opérations fermées, table `RoutesPont.kt` testée). Protections : CSP `script-src 'self'`, aucune injection de HTML dans `site/`, aucune navigation ni requête hors de l'origine interne (service worker compris : non enregistré dans l'appli, et 403 sur toutes ses requêtes), fichiers embarqués par la CI. La page d'essai (`android/essai/`) est encore embarquée dans la version publiée, sans y être servie ; à retirer en E4.
- **Saisie** : écran de saisie exclu de la saisie automatique (pas de proposition « Enregistrer le mot de passe ? », qui enverrait la clé dans un gestionnaire en ligne) et des captures d'écran en version publiée ; le presse-papiers est vidé après « Coller » dans le champ de la clé. Si une proposition d'enregistrement apparaît malgré tout : la refuser.
- **Envoi interrompu** : si la connexion est coupée après l'envoi de l'écriture (autre appli ouverte sans attente en cours, appli fermée), le résultat est « incertain » et la page demande de vérifier dans Smart Life, avec l'heure à régler à la main. L'activité n'est pas recréée par un changement de thème ou une rotation (`configChanges`).
- **Attente en arrière-plan (décision du 2026-11-21)** : « Programmer » touché avant que le téléphone et le câble soient sur le Wi-Fi démarre un service de premier plan `connectedDevice` (non exporté, jamais au démarrage du téléphone, 15 min au plus, verrou d'éveil borné à 16 min) avec une notification « Annuler ». La clé du magasin étant inutilisable téléphone verrouillé (`setUnlockedDeviceRequired`, conservé), **l'identifiant et la clé du câble sont lus au toucher et gardés en mémoire par le code natif, en octets, au plus 15 min**, jamais stockés ni journalisés, mis à zéro à la fin de l'attente dans tous les cas, ainsi que par « Oublier le câble » et l'enregistrement d'une nouvelle clé (accord de Mathieu ; natif depuis E2). Pendant l'attente, le pont reste ouvert appli cachée ; il est refermé à la fin du service. Textes des notifications fixes côté Android (la page ne passe qu'un résultat et une heure validée). Filets de la règle 2 : notification « résultat inconnu » au bout de 15 min, « non envoyée » si l'appli est fermée pendant l'attente. Permissions ajoutées : `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_CONNECTED_DEVICE`, `CHANGE_NETWORK_STATE` (prérequis du type, non utilisée), `WAKE_LOCK`, `POST_NOTIFICATIONS` (seule demandée à l'écran) ; démarrage au boot et alarmes exactes interdits (contrôlé par la CI).
- **Version de mise au point** : débogage WebView et actions par adb (dont « programmer ») ; elle ne va jamais sur un vrai téléphone. Seule la version signée est installée sur les deux Pixel.
- **Pont (depuis E2)** : plus de route TCP générique ; la page ne dispose que d'opérations fermées, listées dans `RoutesPont.kt` (testée) : sur le câble, lire, programmer et chercher, une seule à la fois ; autour, l'état de la configuration, l'ouverture de l'écran natif de saisie, la mémoire de l'attente, les notifications et l'attente. Aucune ne rend la clé ni l'identifiant. Résidu : la clé lue dans le coffre existe un temps comme chaîne de caractères, non effaçable, jusqu'au ramasse-miettes ; seules ses copies en octets sont mises à zéro. Le transport natif (`TransportTcp`) refuse, avant toute socket, tout sauf une adresse IPv4 privée sur le port 6668. Quitter l'appli annule l'opération en cours, y compris avant l'ouverture de la connexion. Aucune opération d'effacement ni d'écriture de la clé n'est ouverte à la page ; l'adresse retenue n'est mise à jour qu'après une lecture réussie avec la bonne clé. Lecture directe seulement si le Wi-Fi du téléphone est sur le réseau de l'adresse retenue ; aucune recherche sans bouton.
- **Installation** : uniquement des APK construits par GitHub Actions depuis `main` et signés par la clé stable ; empreinte du certificat publiée avec chaque préversion et vérifiée. Les versions publiées restent en lecture seule jusqu'au lot C4 (« Programmer » avec le mode Local de la page).

## Vérification périodique (tous les 3 mois, 10 min)

- La liste des appareils visibles par le projet Tuya n'a pas changé de façon inattendue (un nouvel appareil ajouté dans Smart Life y apparaît aussi).
- La double authentification est active sur les trois comptes.
- Aucune alerte de fuite dans GitHub (onglet Security).
- L'accès gratuit à l'API Tuya n'est pas sur le point d'expirer.

## Risque accepté : un agent qui modifie puis lance un outil (2026-11-17)

Pour limiter les demandes d'autorisation, les outils sans secret (`tools/*.mjs` hors scripts protégés, `tests/`) se modifient et se lancent sans demande. Un agent trompé (par un contenu lu sur le web, par exemple) pourrait donc écrire un test ou un outil qui lit `tools/.env` et l'affiche dans la conversation. Accepté par Mathieu le 2026-11-17, avec ces limites :

- `local/` et tous les `tools/*.py` restent protégés : ce sont les chemins directs vers le câble (code exécuté par `node tools/tuya-local.mjs etat`, lancé sans demande) et vers les secrets (un module Python placé dans `tools/` serait chargé par les scripts qui lisent `tools/.env`) ;
- le test `tests/garde-fous-depot.test.mjs` signale un fichier de `tests/` ou `local/` qui lit un fichier de secrets ou ouvre une connexion, et (depuis le 2026-11-22) un fichier de `tests/`, `local/` ou un outil lancé sans demande qui écrit ou supprime en citant un fichier de sécurité (`.claude/`, `tools/hooks/`, `.github/`, `.gitignore`, `worker/wrangler.toml`, `CLAUDE.md`, `SECURITE.md`) ;
- `tools/cle-locale-qr.py` lit et réécrit `tools/.env` : il passe par une demande d'autorisation ; sa sauvegarde `tools/.env.bak` est ignorée par git et ses valeurs sont cherchées par le contrôle avant commit ;
- la relecture par `testeur-relecteur` de chaque lot qui touche `tools/` ou `tests/` ;
- si une valeur secrète apparaît dans une conversation : la traiter comme fuite (procédures de révocation ci-dessus).
